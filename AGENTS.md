# CycleCare project instructions

For UI/UX work, read [`DESIGN.md`](DESIGN.md) and the linked redesign implementation plan before writing code.

- Migrate and extend the approved design consistently across every new screen, feature, sheet, dropdown, dialog and state. Reuse its tokens, icons, components and fluid/reduced-motion behaviour.
- Preserve all existing app elements. The Home phase bar and all phase/window sections are required; the logging catalogue and screen inventory define the full design scope.
- Features marked planned/not implemented need domain, persistence, validation and migration work before their production UI can be described as functional.
- Keep existing health records readable, tracking usable offline and without an account, and partner sharing under explicit user control. Do not turn forecast estimates into medical certainty.
- Keep design artifacts and the actual Flutter implementation clearly distinguished in documentation and completion reports. Do not claim screenshot controls prove production behaviour.

Use focused changes, inspect existing sources first, and run the checks appropriate to the implementation.
